# Owner setup: one new repository and one new deployment

This checklist covers external configuration. No Codespaces, branch merges, local Python setup, or manual test scripts are needed. **A ZIP file is not a GitHub repository by itself; first extract its contents.** Do not upload old BTA versions or any `secrets.toml` file.

1. **GitHub**: https://github.com/new -> repository name `BTA-2.0` -> **Private** -> Create repository. On the repository page use **Add file -> Upload files** and upload all extracted files/folders (including the hidden `.streamlit` and `.github` folders). Confirm `streamlit_app.py`, `requirements.txt`, `.github/workflows`, `assets`, `bta`, `sql` are visible at the root. Commit directly to `main`.
2. **Supabase**: https://supabase.com/dashboard -> New project (Free) -> SQL Editor -> New query -> paste `sql/001_schema.sql` and run exactly once, then run `sql/002_pregame_freezes.sql` to enable immutable pregame evidence records in the NEW project. This sets row-level security, accounts, ticket versions, jobs, shares, and the admin audit. Copy your project URL, **publishable/anon** key, and private **service-role** key. Keep the last key server-side only; never upload it to GitHub source.
3. **Supabase authentication**: Authentication -> Providers -> Email, configure email login but **disable public signups**. Set **Site URL** to your Streamlit URL, add the same redirect URL. In Email Templates -> Magic Link use the HTML in `START_HERE.md` (supports `token_hash` query to Streamlit). BTA provisions the owner and invitations server-side. Do not assume a Supabase default email template works with Streamlit.
4. **Custom outbound email**: Choose Resend https://resend.com (Free if you control a verified sender domain) or the limited Gmail App Password beta fallback from `START_HERE.md`. In Supabase Authentication -> SMTP settings enter the provider's SMTP host, port, username, password and verified sender. The default Supabase SMTP is restricted to authorized project team addresses, not your friends. Don't buy a domain if your rule remains all-free.
5. **AI #1 Groq**: https://console.groq.com/keys -> Create API key -> `GROQ_API_KEY`. Proposed model `qwen/qwen3.8-27b`, subject to the project's actual eligible list.
6. **AI #2 Gemini**: https://aistudio.google.com/api-keys -> Free-tier key -> `GEMINI_API_KEY`, proposed `gemini-3.8-flash`. Review free-tier data-processing terms. Free quotas depend on project/model and can change.
7. **AI #3 Cloudflare**: https://dash.cloudflare.com/ -> Workers AI -> API Tokens -> create restricted Workers AI token -> `CF_AI_TOKEN`, also copy `CF_ACCOUNT_ID`. Proposed model `@cf/openai/gpt-oss-20b` using daily free neuron allocation; don't enable a paid plan.
8. **Optional no-card quote providers**: create free API keys at https://prop-line.com/ and https://parlay-api.com/ . Configure `PROPLINE_API_KEY` (first) and `PARLAY_API_KEY` (fallback) in **Streamlit Secrets and GitHub Actions Secrets**. They may have limited or delayed player-prop coverage; verify license/redistribution terms before member display. Without either key, exact user-entered thresholds remain available; no sportsbook offer is claimed. SportsGameOdds remains an optional legacy adapter, not required.
9. **Streamlit**: https://share.streamlit.io -> Sign in with GitHub -> authorize access to your *private* new repository -> Create app -> repository `BTA-2.0`, branch `main`, main file `streamlit_app.py`. Choose Python 3.12 in Advanced Settings and paste the settings from `.streamlit/secrets.example.toml` into **Secrets**, replacing placeholders with values from your accounts. Use `BTA_MODE="private"`, `BTA_PUBLIC_URL="https://YOURAPP.streamlit.app/"`, and `BTA_OWNER_EMAIL` set to your own address. Never commit actual credentials.
10. **GitHub Actions**: New repo -> Settings -> Secrets and variables -> Actions -> New repository secret. Add `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `GROQ_API_KEY`, `GEMINI_API_KEY`, `CF_ACCOUNT_ID`, `CF_AI_TOKEN`, `CFBD_API_KEY`, `PROPLINE_API_KEY`, `PARLAY_API_KEY`, and `BTA_BACKUP_KEY` (generate Fernet key in owner-only panel) as secret values. Scheduled worker and encrypted backup run best-effort on GitHub's schedule; there is no 24/7 uptime guarantee.
11. **Backups**: The provided workflow encrypts a database snapshot; its built-in SQLite round-trip is NOT a fully proven restoration of Supabase PostgreSQL with RLS. An isolated Supabase/Postgres restoration/security check is still a production launch gate. The project reports this honestly.
12. **Open site and sign in**: BTA shows an invite-only email entry screen once private mode is configured. Owner bootstrap uses your configured owner email. Magic links depend on real SMTP delivery. Owner settings inside the sidebar control member invitations.

## What isn't a one-click free integration

No verified free 24/7 injury + usage feed for every NBA/NFL/CFB market, unlimited sportsbook alt-line coverage, instant unthrottled inference, per-second live tracking, or calibrated probabilities are guaranteed by these accounts. Missing key evidence leads to `PENDING VERIFICATION`; zero-BTA days are allowed. The application is research software, not a sportsbook.

## Privacy and budget constraints

No passwords or API keys in chat or GitHub source. Configure all private values in Streamlit Secrets/GitHub Actions Secrets and Supabase server settings. Review provider terms for redistribution of market data and commercial use before inviting members. Keep free plans unupgraded and review provider usage dashboards. Do not turn on automatic payment methods.
